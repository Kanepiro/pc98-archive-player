# Windows v0.3.43 — 映像停止対策版

モード4の出力MP4で音声は進むのに映像が途中から止まる報告への対策版です。報告された全端末での解消は未確認です。

- 固定のlocalhostアドレスに残る旧Service Workerが、最新版のHTMLと古いJavaScriptを混在させる問題を再現して修正。実行するコードとワーカーをビルド固有のパスに分離し、Windows版ではPWAのキャッシュを使用しません。
- モード4のフレーム取得をHTML動画のシーク・画面読み取りから、ファイルの時刻に基づく連続デコードへ変更。認識と文字変換は同じフレームを使用します。
- フレーム時刻が指定時刻に合わない場合は、古い絵を残り全体に複製せず、変換を停止して知らせます。正当な静止画・元動画24fpsから30fpsへのサンプリング・音声のみの末尾は区別します。
- 旧方式で変換した途中保存データは引き継がず、元動画から作り直します。既存の完成済みMP4は自動修復されません。
- 272文字、輪郭・字形評価、全体組版の探索、解像度と設定fpsは変更していません。DirectCompute/DirectML/NVENCの構成を維持しています。ネイティブGPUバイナリはSHA-256を確認したv0.3.42-rc2と同一です。

旧EXEを終了してから、このZIPを新しいフォルダへ展開し、その中のTASL-PC-Boost.exeを起動してください。元動画を選び直し、再変換してください。

確認内容は同梱FREEZE-VALIDATIONを参照してください。旧キャッシュを残した起動、65秒・1950フレームの読み取り、時刻異常・真の静止区間、Windows梱包EXEでのモード4→音声付きMP4を検証します。Windows CIはWARPソフトウェアGPUを明示的に使います。GTX 1050 Ti / DirectML / NVENC実機で今回の停止が解消するかは、ユーザー環境での再確認が必要です。

報告された添付6本では4本が3.47〜57.57秒で停止し、2本は最後まで更新されました。キャッシュ混在は再現した不具合ですが、元の実行時ログとTSLがないため、添付4本すべての原因を確定したという意味ではありません。以前のVALIDATIONフォルダと各レポートは、変更していないv0.3.42-rc2のGPU実装に関する履歴です。
