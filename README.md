# PC-98 Archive Player

MAG画像・TSLテキストアニメ・M-MASL (.MMS) を、AndroidのChromeから開く統合プレーヤーです。バージョン0.3.32は検証版です。APKではなく、ホーム画面に追加できるPWAです。

**起動URL:** https://pc98-archive-player-seven.vercel.app/

**GitHub:** https://github.com/Kanepiro/pc98-archive-player （公開）

## 使い方

1. 配布URLをChromeで開きます。
2. 「ファイルを開く」で端末のMAG / TSL / MMSを選びます。
3. MAGは画像を表示します。TSL / MMSは「再生」を押します。
   「文字色」「背景色」はプレーヤー画面に常時表示されます。色はいつでも変更でき、再生画面・MP4保存にも反映されます。Androidでカラー選択後に画面が更新されない場合は「色を反映」を押してください。直下に反映済みの色コードが表示されます（TSLファイルは変更しません）。MAG・MMSの表示色には影響しません。
4. 「停止」「音量」「全画面」を必要に応じて使います。MMSの選択肢には「作品内のキー操作」を使います。
5. 「MP4保存」を押すと、作品を端末内でH.264/AACのMP4に変換して保存します。進行中は「変換中止」を押せます。

MP4保存：MAGは5秒の静止動画、TSLは無音アニメーション、MMSは映像と内蔵音声を変換します。画面録画ではなく作品データから直接生成するため、操作ボタンや通知バーは映りません。MMSはキー未入力の既定経路を出力します。映像・音声が止まったままキー入力を待つ作品（例：『ｽﾜﾝ.MMS』）は、3秒間新しい映像・音声がないことを検知し、最後の内容から0.6秒後までを書き出します。実際に3秒以上の無音・静止を演出として含む作品では途中で切れる可能性があります。インタラクティブ作品・無限ループは最後まで自動書き出しできない場合があり、上限は5分です。H.264対応のChromeが必要です。AAC非対応ブラウザーでは同梱のWebAssembly AACエンコーダーを使います。Android実機での機種別動作は未検証です。

v0.3.4以降では旧PWAキャッシュに新旧ファイルが混在しないよう、更新ごとにアセットを一意のURLで取得します。旧版を使っている場合は https://pc98-archive-player-seven.vercel.app/?v=0.3.15 をオンラインで一度開いて更新してください。

Chromeメニューの「ホーム画面に追加」でアプリとして起動できます。「オフライン準備済み」表示後はアプリ本体をオフラインで開けます。作品は端末からその都度選びます。画面を離れると停止します。停止後の再生は先頭からです。

選んだ作品のデータをサーバーへ送信する処理はありません。配布元へのアプリ取得の通信は発生します。「動作確認データ」はこの開発用に作った12秒の映像と連続音です。元の作品や旧プレーヤーは同梱していません。


## 動画 → TSL（0.3.0）

### 変換方式（v0.3.32）
- **モード1：従来の濃淡変換** — 16種類のASCII文字で明るさを表現。エンジン・出力結果は従来と同一。
- **モード2：丸だけの新聞網点（。ｏ○◎）** — ユーザー指定の句点「。」と全角「ｏ」「○」「◎」に空白を加えた5階調。明部は空白、暗部は◎。句点は中央ではなく左下寄りだが、指定どおり使用。固定配置の4×4網点ディザを適用し、同じ映像が同じ結果になる。
- **モード3：高画質・ちらつき抑制** — XDoG（差分ガウシアン線画抽出）、Edge Drawing系の線のつながりの追跡、実際に描画した全角・半角文字の字形マスクとの照合、フレーム間のヒステリシスを組み合わせる。ベタ塗り領域は空白にし、抽出した輪郭のみ文字化する。
- 過去のモード2（輪郭だけ＋塗りは空白）は廃止済み。現在のモード2は新しい新聞網点方式であり、旧TSLファイルの再生互換性は維持。
- モード3のTSLはCP932/Shift-JISで保存。全角は2列、半角は1列。自動的に文字サイズに応じて文字数が変わる。

1. 「動画 → TSL」タブでMP4を選択、または1本ドラッグ＆ドロップします。この段階では変換しません。
2. 最初から開いている変換設定を確認・変更し、設定の下にある「変換」ボタンを押します。進捗と中止ボタンを表示します。
3. 「TSLをダウンロード」で元動画名.TSL（モード2は元動画名_Mode2.TSL、モード3は元動画名_Mode3.TSL）を保存します。「プレーヤーで再生」または「全画面で再生」で確認できます。再変換するときは設定を変更して再度「変換」を押します。

標準はスマホ縦9:16（文字サイズ24px相当・75列×67行）、10 fps、中央切り抜きです。文字セルの比率0.5を考慮して新しい縦長の画面データを生成します。
「変換設定（任意）」の「文字の描画」メニューは「従来のpx指定」が標準で、「16×16ドット（PC-98実寸）」も選べます。従来の「文字の大きさ（px）」には16〜256を入力できます。9:16では24px（標準）なら75列×67行、20pxなら90列×80行、40pxなら45列×40行、128pxなら14列×12行、256pxなら7列×6行です。大きくすると文字を少なく・大きく描け、文字が潰れにくくなる場合があります。文字のpx値はTSL内に保存せず、文字数・行数として反映します。MP4に書き出す際は拡大した画像の引き伸ばしではなく、出力解像度で文字を描画します。端末がフルHD H.264に対応しない場合は解像度を下げます。
新しい「横16:9（1920×1080）」では元動画を右回転せずに文字を正立させたまま変換します。24px設定では128列×36行（12×24文字セルで正確に16:9）になり、MP4保存では端末が対応する場合1920×1080へ再描画します。24fpsも選択可能です。縦9:16に回転した動画ではなく、元の1920×1080動画を選んでください。
「この端末の縦画面比率」ではscreenの縦横比から列数・行数を計算します。上限100行に合わせて列数を調整します。PC-98向けモードの文字数は固定でpx指定はできません。
そのほかfps、明るさ、コントラスト、ガンマ（標準1.0、0.4〜2.5）、色の輪郭補助（標準0.6、0〜1）、切り抜きの左右・上下位置を調整できます。ガンマを1より小さくすると暗い部分が明るくなり、1より大きくすると明るい部分の濃淡を出しやすくなります。輪郭補助は明るさの似た別の色の境目を文字濃淡として少し強調します。効果は映像によります。旧方式と同じ変換結果にするにはガンマ1・輪郭補助0にしてください。「全体を表示」は余白ありで動画全体を収めます。なお「色の輪郭補助」はモード1専用で、モード2・3では使用しません。
全画面では操作パネルを隠し、既存の再生エンジンと同じcanvasを使います。タップすると「戻る」が現れます。
Fullscreen APIを利用できない場合はブラウザー表示領域いっぱいに表示します。ブラウザーやOSのバーを必ず消せるわけではありません。
文字を縦横別々に拡大する処理はありません。

| モード | 用途・互換性 |
|---|---|
| スマホ縦9:16 / 端末比率 | このWebプレーヤー向け。元のPC-98 TASLの標準画面範囲（160×50等）を超える場合があり、PC-98で全画面表示できるとは扱いません |
| 横16:9 | 横長動画をそのまま文字アニメ化。文字は回転させません。最大幅160列、セル比0.5で比率を保持。MP4はフルHD対応時1920×1080、未対応時は解像度を下げます。Webプレーヤー向けです |
| PC-98向け | 79×27（標準）、80×25、120×40、160×50。実データとTASL Ver.1.08説明書に準拠。実機・エミュレーター再生は未検証 |

対応確認: MP4/H.264、WebM/VP9（Linux Chrome）。MP4内のすべてのコーデックを保証するものではありません。
WebMはそのブラウザーがデコードできる場合に利用できます。音声はTSLへ保存しません。
入力上限2 GiB・2時間・約830万画素。出力上限10,000画面・192 MiBに合わせて実効fpsを自動で下げます。
長尺を切り捨てる処理ではありません。総時間は60 Hz単位に丸め、通常は誤差1/120秒以内です。
処理は端末内で完結し、変換Workerもオフラインキャッシュに含まれます。

### 途中保存・再開（v0.3.5）

動画→TSLの変換中は16画面ごとに変換済みデータを端末のIndexedDBへ途中保存します。アプリを閉じたりOSが停止させたりすると、そこで変換処理そのものは停止します。アプリを開き直し、「動画→TSL」で同じ動画を再選択し、「続きから再開」を押すと、最後に保存された画面から変換を再開します（未保存の最大15画面は再変換）。変換設定は自動復元します。完了直後に閉じて保存し損ねても同じ動画を選ぶと「結果を復元」できます。

元動画は保存せず、先頭・中央・末尾のサンプルハッシュで同じ動画であることを確認します。以前の別の動画や別の設定で新規変換を開始すると前回の途中保存は上書きされます。ブラウザーのストレージ削除・容量不足・シークレットモード等では途中保存が利用できないことがあります。完全に閉じたPWA内でのバックグラウンド変換継続はできません。

[TSL出力仕様と互換性](verification/tsl-converter-format.md) / [検証記録](verification/tsl-converter-tests.md)

再現用の人工動画はFFmpegで作成できます。既存作品を試験動画に流用していません。

```sh
node scripts/converter-fixtures.mjs
npm test
npm run build
# 別ターミナルで PORT=4184 npm run dev
PLAYER_URL=http://127.0.0.1:4184/ npm run test:converter
# 途中再開テスト：FFmpegでverification/private/resume.mp4を作成してから
PLAYER_URL=http://127.0.0.1:4184/ npm run test:resume
# 横16:9の実動画→TSL→1920×1080 MP4一貫テスト
PLAYER_URL=http://127.0.0.1:4184/ npm run test:landscape
```


## 実装

- MAG: MAGBIBLE.DOCと正誤表に基づく独立実装。16/256色、部分保存、縦長ピクセル。GRBパレットの格納値を保持。
- TSL: ユーザーの既存TSL_Viewer.htmlを基に移植。Shift-JIS、絶対時刻による再生。1178画面の実ファイルに対応するため旧300画面制限を修正。
- MMS: このプロジェクトのWindows版v0.2のC++エンジンをEmscriptenでWebAssembly化。旧MM32.EXEやWinGを実行しません。
- 音声: WorkerからAudioWorkletへ直接PCMを渡し、20msブロックを12個先読み。UIが一時停止しても音声供給を継続します。
- MP4: 専用WorkerでMMSのフレームとPCM音声をオフライン生成。音声・映像を別々のWorkerから並行生成し、muxerのバックプレッシャー待ちを回避。WebCodecsとMediabunnyでH.264/AACをMP4へ多重化。AACエンコード非対応環境ではFFmpeg AAC（WASM）で代替。
- 同期: 出力済みサンプル数とAudioContextの出力時刻を基準に映像を選択。遅れた映像を追いかけて音声を止める処理は行いません。
- PWA: 内容ハッシュでキャッシュを更新。「更新を適用」で待機中の更新を切り替えます。

## 開発とテスト

Node.js 22とnpmを使用します。

```sh
npm ci
npm test
npm run build
npm run dev
```

http://127.0.0.1:4173/ で動作します。AudioWorkletとService WorkerにはHTTPSまたはlocalhostが必要です。HTMLファイルを直接開いても動作しません。

C++を変更した場合はEmscripten **3.1.69**で再生成します。

```sh
git clone https://github.com/emscripten-core/emsdk.git tools/emsdk
tools/emsdk/emsdk install 3.1.69
tools/emsdk/emsdk activate 3.1.69
npm run build:wasm
npm test
npm run build
```

生成したpublic/mms-core.mjs、public/mms-core.wasm、src/mms/wasm-source.sha256をソースと一緒にコミットします。通常ビルドはソースハッシュの不一致を検出して中止します。Vercel側でSDKを毎回ダウンロードする必要はありません。

実サンプルを所有している場合のみ、reference/MAGとreference/TASLに読み取り用コピーを置きます。MMS_ROOTでMMSフォルダーを指定します。

```sh
MMS_ROOT=/path/to/MMS npm run test:corpus
MMS_ROOT=/path/to/MMS CHROME_PATH=/path/to/chrome npm run test:browser
```

ブラウザー試験はLinuxテスト環境向けのスクリプトです。MMS_ROOTでMMS試料フォルダーを指定してください。npm run devを別ターミナルで起動してから実行します。作品や画面キャプチャーはGitへ追加しないでください。

## GitHubとVercel

GitHubがソース管理先、Vercelが配布先です。VercelのGit連携は接続済みで、mainへのpushから自動デプロイします。Build Commandはnpm run build、Output Directoryはdist、Install Commandはnpm ciです。変更をブランチへpushし、Previewで確認してからmainへ反映します。

GitHub Actionsはnpm testとnpm run buildを実行します。APIキー・データベース・ユーザー登録は必要ありません。Vercelの既定のアクセス保護は維持します。

### 2026-11-10: MP4保存の応答性・モード2の細い輪郭（v0.3.11）
- TSLのMP4エンコードを専用Web Worker＋OffscreenCanvasへ移行。描画と動画圧縮を画面のメインスレッドから切り離すことで、長尺変換中も進捗表示・中止操作を維持。
- エンコーダーが35秒間応答しない場合、ワーカーを終了してHD画質で一度だけ再試行。中止した場合はワーカーを即終了する。
- MP4保存で使用するTSLデータはShift-JISの元ファイルをワーカー内で再解析し、画面上の表示色・背景色も維持。
- モード2では全角2列の平均化前の半角1列ごとの画素も解析し、細い輪郭をASCIIの線記号で補足。輪郭感度の標準値は40→20、選択範囲は5〜140。平坦な塗りは引き続き空白。
- 新しいモード2の結果に旧版の途中保存を混ぜないため、モード2の保存シグネチャのみ更新。モード1の再開と変換結果は従来どおり。
- Chromeのヘッドレス環境で1100画面の変換中UI応答／即時中止、16秒H.264の完全出力、フルHD・HD fallbackを検証。Android実機は未検証。

### 2026-11-10: 動画向けモード3へ置き換え（v0.3.13）
- モード2を廃止し、局所の字形・元画像の色差と濃淡・つながった線を比較するモード3へ変更。
- 文字候補は実際の表示用canvasと同じフォントで描画して標本化。画素の分布を各候補字形と比較し、全角・半角の列幅を考慮して動的計画法で配置。
- フレーム間の元画像変化が小さい場所では同じ文字を保ち、シーン切替では履歴を解除。中断再開時も前フレームの字形と画像状態をIndexedDBへ保存して復元し、フレーム列が一致することを実証。
- モード1と既存のTSL表示・MP4書き出しは変更せず、旧版モード2のTSLも引き続き読み込み可能。

### 2026-11-11: モード3のベタ塗り背景ノイズ除去（v0.3.13）
- 背景色との差による面表現（globalInk / localInk）を撤廃し、XDoGとつながった輪郭線のみで字形マッチング。
- コントラストの弱いエッジは閾値で取り除き、輪郭が消えた場所で前フレームの文字を引きずらない。
- 移動物体がグラディウスのオプションのように残像を引かないよう、過去フレーム画素の混合を廃止。文字を維持するのは同じ位置に輪郭が重なる静止部分だけ。移動図形の背後が空白になる自動テストを追加。
- 平坦なセルの文字残りを明示的に禁止。モード1、旧TSLの再生とMP4出力は変更なし。
- 再開時に旧版の変換済み文字を混ぜないよう、モード3のチェックポイントエンジン番号を6へ更新。

### 2026-11-11: 音声付きMP4ワンクリック書き出し（v0.3.15）
動画→TSLの変換設定に「MP4へ直接変換（元動画の音声付き）」チェックを追加。ONなら変換実行ボタンひとつでTSL生成後、同じ元動画の音声トラックを合成してMP4を保存します。TSL単体のダウンロードも可能。元音声がAACならパケットを再圧縮せず収録し、WebMのOpus等はAACへ再符号化します。音声トラックのない動画では音声付きMP4生成に失敗を表示し、完成TSLは保持します。5分超のMP4化は現行の動画書き出し制限に従います。モード3の巨大図形（○●□■◇◆）禁止に伴い途中保存互換バージョンを7へ更新し、旧パレットの途中データを混在させません。

### 2026-11-11: Mode3のWebGPU自動高速化（v0.3.15）
Mode3の字形照合の相関計算を、対応環境ではWebGPUのcompute shaderへ移行できるようにしました。線画抽出(XDoG/輪郭追跡)と表示文字の動的計画法、ちらつき抑制は従来のCPUロジックを維持します。起動時にGPUの演算経路を準備し、最初の1画面でCPU演算と速度および精度を比較します。GPUのほうが十分に速く（約10%以上）、照合結果が一致する場合のみGPUを継続使用。GPU未対応、遅いソフトウェアGPU、デバイス損失の場合は既存のCPU変換へ自動フォールバックします。GPUを使う場合も生成文字パレット（○●□■◇◆禁止）は同一です。RDC接続Linux機でWebGPUをSwiftShaderエミュレーションしてCPU/GPUの6画面一致・ワーカー起動・自動フォールバックを検証。実機GTX 1050 Tiでの高速化率は未測定です。

### 2026-11-12: モード2「新聞網点」を新設（v0.3.16）
- 空白・全角「・」・全角「●」の3階調だけを使う独立したモード2。旧モード2とは別方式。
- CP932/Shift-JISのTSLへ保存し、既存のプレーヤー・MP4書き出し・元音声付き直接MP4変換・中断再開と統合。
- 階調の境目では固定の4×4順序ディザを使用。輪郭抽出はせず、文字セル内の平均輝度を使う。

### 2026-11-13: モード4の意味理解・構造組版の統合（v0.3.30）

- **画像認識**: MediaPipe Vision (Apache-2.0)、BlazeFace（顔6点）とEfficientDet-Lite0（人・猫・犬・鳥など）の事前学習モデルをブラウザ内のCPUで実行。顔・人物・動物の検出結果に応じて重要部分を重み付け。入力動画や各フレームは外部に送信しない。
- **重要な構造**: 連結輪郭のノイズ削減、Zhang–Suen細線化による骨格・端点・分岐点・線分グラフの抽出。細部が文字のノイズにならないよう、主役と意味的特徴を優先。
- **構図**: 検出された顔が小さい場合のみモード4内で被写体へ穏やかにズーム。主役が十分大きければ元構図を維持。前後フレーム間で画角を平滑化。
- **文字部品**: これまで選定された272字を一文字ずつ実描画し、画素形状・文字幅・描線方向・端部接続を分析する。指定外の字は使用しない。
- **ブロック組版**: 2行のCP932半角/全角可変幅字を同時にビーム探索する最適化を追加。左右・上下の線接続と元の主輪郭、全体損失を評価して改善した変更だけを採用。全画面の反復組版も維持する。
- **動画安定化**: 同一フレームは全画素照合して文字アートを再利用、静止場面の処理費用を抑制。映像が動けば文字を再評価する。途中再開互換番号は18。
- **通信・オフライン**: JS実装は同梱。学習済みモデルとMediaPipe WASMのみGoogleの公開モデル配布URL・jsDelivrから初回ダウンロード。認識データを取得できない場合は、被写体意味認識なしの構造解析へフォールバック。モデルファイルは初回利用時に約16MBの通信が発生することがある。
- **制約**: 静止写真1枚から文字アートを作成する処理としては完成したが、人間のAA職人が行う場面の意味解釈・デフォルメ・創作までは模倣できない。96pxの巨大文字設定では再現できる細部が少なく、さらに小さい文字サイズを選べる。

### 2026-11-13: 全モードWebGPU計算対応（v0.3.32）

- モード1：GPUで画素ごとの平均RGBと文字濃淡・輪郭補助を並列計算。CPUとの文字列一致を毎フレーム検証し、異なる場合はCPU出力を使う。
- モード2：GPUで平均輝度、5階調への変換、固定Bayerディザを計算。CPU出力との完全一致が品質条件。
- モード3：既存のWebGPU字形照合を活用。初回にCPUとの数値一致を検査し、正しければGPU使用を優先する（以前の『GPUがCPUより10%以上高速な場合のみ』という速度判定は廃止）。
- モード4：GPUで272文字×配置候補の形状照合を並列計算。画像輪郭と字形の誤差、線の方向、時間的一貫性、顔の重要領域を同じ式で評価。CPUとの数値誤差を標本照合し、基準外なら自動でCPUへ切り替える。複数行ブロック組版と全画面自己評価など、並列化が不利な処理はCPUのまま維持する。
- どのモードもWebGPU非対応・GPU検証失敗では従来のCPUで動作する。TSL/MP4の書式や既存モードの画質設定、モード4の272文字は維持する。
- 端末やブラウザーでのWebGPU利用可否・速度は異なる。CPUフォールバックを含めて動作する。
