# 既知の制約と未確認事項

- Windowsの実機はWindows 10／AMD Phenom II X6／GTX 1050 Ti。Windows 11、およびWindowsネイティブ版のIntel CPU・AMD GPU・Intel内蔵GPUは実機未確認。Web CPU経路はIntel Core M-5Y10cのLinux実機で測定した。一般的なx64/SSE2ビルドと既存CPUフォールバックを維持した。
- Android/iOSの既存実装はブラウザー/PWA。APK/IPAや新しい署名パッケージは作成していない。Linux Chromiumのモバイル表示、CPU経路、Linux WPE WebKitで代替検証した。実機の発熱・電力・長時間動作を確認したものではない。
- Linux WPE WebKitのモード3は、公開版と候補版の両方でU+2015の細線がCanvas縮小時に消える問題がある。字体やサンプル密度を変える修正は採用していない。iOS Safariで同じ問題が起きるかは未確認。
- WindowsのNVENC成功経路とDirectMLは未確認。今回のMP4圧縮はlibx264 CPU経路で、文字描画にはDirectComputeを使用した。NVIDIA固有の処理を必須にしていない。
- モード3/4は公開版のCPUとGPUの間に数値演算・丸めによる差がある。候補版は各バックエンドの公開版出力を維持した。異なるバックエンド相互で同一TSLになるという保証ではない。
- Windows短尺MP4は欠落していた最終フレームを追加しており、旧版MP4のバイト列や末尾の復号画素とは一致しない。共通部分の圧縮前文字画素とエンコード品質設定は維持した。詳細はQUALITY-AND-STABILITY.md。
- GPU計算失敗からのCPU復帰とcheckpoint再開を検証した。実ドライバーリセットやOSクラッシュは注入していない。ホスト全体が失われた場合は保存済みcheckpointからの再開が必要。
- Windows/Webのモード1/2は、完成MP4までの改善が小さいか一貫しない。Windows長尺モード1には約5%の時間増加もあった。内部GPU処理や転送時間は短縮したが、動画シーク・画素取得が総時間を占める。品質不一致を起こした逐次デコードやHTMLVideo先読みは採用していない。
- 初回候補のHTMLVideo先読みはWindows長尺モード3でTSL不一致が出たため撤回し、影響する測定を更新した。初回Webの短尺7試行にはCPU/RSS欠落があったが、改訂版は全56試行を測り直した。旧試行も不採用記録として保持し、最終中央値へ混ぜない。
- GPU使用率・VRAM値はGPU全体の値。RSSはプロセス別常駐量の合計で、共有ページの重複を含み得る。
- Playwrightの全ページ撮影後にCSS FontFace参照が無効になる現象をWindowsの両版で確認した。撮影を操作試験の最後に置いた。通常操作の検証結果とは分けて記録した。
- 検証素材は公開版Windows最大120秒、Web CPU最大30秒。すべての動画形式・内容・長さ・端末の完全な検証ではない。
- 今回の候補をGitHub/Vercelへ公開していない。既存配布ファイルの差し替えや既存ファイルの削除は行っていない。
