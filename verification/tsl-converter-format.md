## 出力契約

- エンコーディング: ASCIIのみを使用するためShift-JISと同一バイト。BOMなし。ダウンロード名は元動画のUnicode名を保持する。内部タイトルはASCIIの Video conversion。
- 改行: CRLF。ヘッダーは version / count / width / height / x / y の6行、続いてタイトル。
- version=1.08、x=1、y=-1。画面数と文字サイズは実際の生成結果を記録する。
- 区切りは行頭のFF(0x0c)+CRLF。ヘッダー→スケジュール→各画面→末尾FF→DOS EOF(0x1a)。
- スケジュールは1始まりの画面番号と、整数の1/60秒ticks。最後は 0 0。
- 各画面は幅ちょうどのASCII文字列を高さ分。スペースも行頭の#も保持する。
- TASL.TXTでは1.04以降は画面中の#や空行をスキップしない。1.07以降は旧スケジュール数・画面数制限を撤廃。最大行長512バイト。出力最大幅160+CRLFはこの範囲内。
- 0 0 は当時のTASLではキー待ち。既存Webプレーヤーでは再生終了として扱う。ネイティブの自動終了を意味しない。
- 元動画のdurationを最も近い60 Hz tickへ丸め（最低1 tick）、累積境界を丸めて各画面のticksを算出する。通常の総時間誤差は最大1/120秒、1 tick未満の動画は最大1/60秒未満。各フレーム個別の丸めを加算しない。
- browser seekはこのスケジュールの絶対開始時刻で行う。元動画の全フレームを保持する変換ではなく、指定fpsでの時間サンプリング。VFR動画もブラウザーの時間軸でサンプリングするが、多様なVFRコーデックの網羅試験は未実施。

## 文字の明度・縦横比

既存drawTSLをそのまま使い、16文字を1文字ずつ描いてRGB総量を測定し、暗→明で並べ替える。
Linux Chrome 157での測定結果は「 .:/|(Y$#V%0O8@D」。端末の等幅フォントに合わせて毎回測定する。
歴史的なPC-98フォントの濃度再現ではなく、現在の統合プレーヤーで明度順が逆転しないことを目的とする。
変換はセルごとに4×4サンプルの平均輝度（Rec.709係数）を使う。明度とコントラスト調整後、16段階へ量子化する。
既存の12×24セル（縦横比0.5）に合わせ、元動画と文字の縦横比を保つ。containは黒余白、coverは切り抜き位置に合わせたクロップを行う。
スマホ標準は90×80文字で正確に9:16。端末比率はscreenの短辺/長辺を使用し、90列基準で行数を計算、100行を超える場合は列数を減らす。最大の比率誤差は文字セルの整数丸めによる。
横16:9では1920×1080の元動画を無回転で、12×24文字セルの横長の格子へ描画する。24px設定では128×36文字（実画面比16:9）。TSL再生・MP4書き出しでも文字を回転させない。端末がFull HD H.264をサポートすると1920×1080、それ以外はフォールバックする。
縦画面TSLはWebプレーヤー向けで、PC-98 TASLの標準画面範囲を超える。PC-98モードは79×27等の従来寸法を保持。

## メモリとエラー

動画本体はFileのobject URLでブラウザーに渡し、JSで全動画をarrayBuffer化しない。
同時に保持するRGBAは1フレーム分（最大640×400）。文字変換は専用Worker、64画面ごとにBlobへまとめる。
最大10,000画面かつ48 MiB以内の見積もりに合わせて実効fpsを下げる。上限は2 GiB、2時間、3840×2160相当の画素数。
最終Blob、ダウンロード、既存プレーヤーでの再読込には出力に比例するメモリが必要。端末固有の不足まで保証しない。
各decode/seek/worker応答には30秒のタイムアウト。中止時・エラー時・完了時にWorker、video.src、入力object URLを解放する。
出力URLは再変換時に解放。完成前の部分データはダウンロードしない。
既存CSPにmedia-src 'self' blob:のみ追加し、端末の動画を許可した。Vercelのアクセス保護設定は変更しない。

## 互換性の範囲

生成TSLは既存parseTSL / drawTSL / tslFrameAtとopenFileを再利用して再生する。MAG・TSL・MMSエンジン、MP4エンコーダーに変更なし。
TASL Ver.1.08の資料と実データに準拠するが、PC-98実機・エミュレーターでの生成TSL再生は未検証。
WindowsブラウザーとAndroid実機は未検証。Linux Chromeのモバイル画面エミュレーションを実機試験と混同しない。
